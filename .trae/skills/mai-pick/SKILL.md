# 麦搭

复用随包提供的网页和确定性核价逻辑。让使用者在自己的浏览器中连接官方账号，禁止向使用者索要聊天中的 token。

## 运行

1. 以此文件所在目录为 Skill 根目录，运行 `node scripts/launch.mjs --check`。要求 Node.js 20.19+ 或 22.12+、npm 和本机浏览器。缺少这些能力时说明限制，不声称在线试用环境可以运行。
2. 首次运行 `node scripts/launch.mjs --setup`。将源码复制到当前操作系统用户的私有数据目录，从 npm 官方源安装锁定依赖并在该目录构建网页；成功后才标记可运行。不修改安装的 Skill，不读取项目 `.env`。
3. 在可持续运行的后台终端运行 `node scripts/launch.mjs --serve`。读取脚本打印的 `http://localhost:3011`，并在使用者的本机浏览器打开。仅监听 localhost，默认端口为 3011；端口占用时明确报错，不停止已有程序或复用身份不明的服务。可使用 `--port 3012` 等空闲端口。
4. 让使用者在首次连接引导中自行打开 `https://open.mcd.cn/mcp`，登录本人账号并获取 token，再手动粘贴至网页密码框。Agent 不查看输入值、Cookie、浏览器存储或请求认证头，不截图含 token 的区域。
5. 连接完成后，确认取餐方式、城市和门店。缺少营养和口味信息时询问关键条件；未提供时使用网页默认条件，并明确这是默认值。通过「我的偏好」设置预算、热量、蛋白质、钠、忌口、饮品和星期安排。
6. 使用「帮我搭一餐」取得最多三个核价方案。优先展示套餐和随心配、可用优惠券以及实际金额，并说明核价的候选数和未覆盖范围。详情与规则见 [核价和凭证边界](references/usage.md)。
7. 用户想查活动、领券或省钱时打开「优惠与领券」。展示当前可领券、本人券包到期日、门店可用券和近期活动。只有用户明确要求领券时，点击「一键领取所有当前可领券」；官方接口不能指定单张券。完成后重新搭餐和核价，活动宣传价不能当作本单实付。
8. 用户想复用搭配时可「存为常点」，在「常点与预算」按今日优惠重新核价。月预算是复盘和余额提醒；同步官方状态后，只计入确认已支付的本工具订单。报价、已创建待付款订单、券面金额不算已省或已花。

## 操作边界

- 只使用当前浏览器会话操作网页。不要从磁盘寻找他人的会话、Cookie、token 或 `.local`，也不要跨会话调用后端 API。分享的是指令和代码，不分享账号。
- token 只能由使用者自行填写，或由宿主明确提供的个人私密凭证机制注入；本包没有预置凭证，也不提供聊天粘贴 token 的入口。网页连接是本包已实现的路径。
- 默认只查询、推荐与核价。点击「确认提交，前往官方支付」会创建真实订单；只有在当前餐品、门店和实时金额已展示且使用者明确授权提交后才操作。不要因“帮我搭一餐”自动提交。使用者自行在官方页面支付。
- token 更新、会话变化或报价过期后重新核价。提交结果不确定时让使用者在官方 App 核实，不重试创建订单。
- 领券属于账户操作，默认查询不领取；用户已经要求“一键领券”时可继续，不重复请求授权。不要代购会员卡、兑换积分或凑单购买。领券结果不明确时先在官方 App 核实，不能自动重试。
- 节省金额使用官方同一购物袋的原价与现价之差，或相同餐品份量在同门店、同渠道下的单点核价差；两者不相加。缺少可比原价时明确金额未知。满减差额只作提示，加购须重新核价并检查营养与预算。
- 没有浏览器控制能力时提供本机 URL，让使用者在网页完成操作。不能访问使用者浏览器的 Cookie 时，不改用任意新会话绕过。
- 关闭服务不撤销官方 token。使用者可在「连接设置」断开并删除该会话数据；退出后台服务后内存中的凭证随进程释放。

## 共享

此包用于安装到具有本机执行能力的宿主。上传到扩展市场只分发源码，不等于部署成公网服务；平台在线试用的执行和凭证隔离能力需要另行验证。根据预期受众选择空间，上传窗口未选择空间可能默认公开。发布包不得包含 dist、node_modules、__pycache__、`.env`、`.local`、用户数据目录、Cookie、调试输出、个人地址、优惠券或订单数据。构建产物只生成在使用者的私有运行目录。
