# 核价和凭证边界

## 确定性推荐

- 使用官方 `list-nutrition-foods` 按准确份量匹配；营养未知不能当作零，不参加自动推荐。
- 获取门店菜单、完整套餐轮次和本人可用优惠券；套餐内部也检查营养、饮品和忌口。
- 热量区间、最低蛋白质、最高钠、预算和排除名称是硬条件。无解时说明哪些条件可能需要调整，不能擅自放宽。
- 从营养达标组合中按估价选最多 24 个不同低价候选，官方核价后按实付排序；同价时才考虑口味、天气和星期。每种不同主食最多展示一个，最多三个方案。
- 实付金额计入官方返回的配送、打包费；推荐不含餐具，结算按餐具选择再核价。优惠券必须来自本次账户和门店；查询不会领券，明确要求领券后才操作，不使用其他人的券。
- 搜索限定单人餐，最多一份主食或套餐，再补一份小食和饮品。复杂套餐可能只比较默认组成。不宣称全菜单或跨平台全局最便宜。
- 天气为 Open-Meteo 城市级数据；查询失败时关闭天气排序。18°C 及以下优先热饮，27°C 及以上优先清爽饮品。星期和日期使用 Asia/Shanghai。
- 默认热量 350–750 kcal、蛋白质至少 25 g、钠最多 1800 mg、预算 45 元；默认城市为上海，使用前确认是否适合本人。排除名称不能替代过敏原验证。

## 用户凭证

- 共享 ZIP 只含源码、指令和锁定依赖清单。网页在使用者本机的私有目录构建，构建产物不上传。每个人自行从官方平台获取属于自己的 token。
- token 是可授权调用账户服务的 Bearer 凭证，应该按密码保护。不要写进 Skill 描述、示例、Git、平台公共变量、聊天、截图或日志。
- 连接使用者 token 后只存服务端内存；网页不会回显已配置值，验证完成清空输入框。项目环境变量中的 token 不作默认凭证。
- 后端按随机 HttpOnly Cookie 分会话；同一浏览器配置的标签页共享连接，不同浏览器或独立无痕会话分别连接。换连接版本后旧标签页请求和旧报价失效。相同 token 的两个会话也分开保存本地数据。
- 每个操作系统用户的 Skill 运行目录独立。网页通过 localhost 访问，服务只在本机监听；所有官方和天气请求使用域名。会话偏好、报价和本工具订单状态写入该用户目录，而不是发布包；目录权限 0700、文件 0600。此权限不防同一操作系统账号的其他进程或机器管理员。
- 新会话有效 90 天；重启服务后 token 不保留，重新验证同一 token 可恢复未过期会话的偏好、常点和记录，旧报价不可提交。旧版会话沿用原到期时间。断开时删除整个会话，官方已创建订单不被取消。
- Skill 指令无法阻止拥有运行环境访问权限的程序读取进程内存；它也不能自动提供云平台多租户安全。云端部署应以平台认证、私密凭证存储和用户隔离的后端实现约束，而不是仅靠 SKILL.md。

## 故障

- 依赖安装失败：保留错误说明，检查网络与 npm 官方源是否可访问；不要转用未知下载站。
- 端口被占用：不终止现有服务，使用脚本支持的另一个本机端口。
- 401、token 无效或已过期：让使用者在官方平台重新获取并在网页更新，Agent 不代读凭证。
- 接口限流：等限流恢复，不自动重试创建订单。
- 报价三分钟有效；价格变化要求再次确认。创建结果不明必须在麦当劳 App 核实。
- 没有本机 Node.js 或浏览器的纯聊天宿主：本包无法直接运行。需要宿主提供每用户授权的 MCP 与执行能力或部署配套服务，不宣称当前包已经支持。

## 优惠、金额与重复使用

- `available-coupons` 查询当前可领麦麦省券，`campaign-calendar` 查询官方近期活动，`query-my-coupons` 分页读取本人券包。仅限 App 的券保留渠道说明，不混入本工具可用券。`query-store-coupons` 负责门店和取餐方式筛选；最终仍需 `calculate-price`。
- `auto-bind-coupons` 一次领取所有当前可领麦麦省券，只在用户明确授权后调用。不支持指定活动券领取、付费开卡或积分兑换。领券后清除缓存与旧报价，重新推荐；不保证领券一定能降低本单实付。
- 领券请求有独立编号和状态，重复请求不重复领取。网络失败会标记待核实；只有用户在官方 App 核实后才能恢复检查。活动文章、到期券提醒不触发购买。
- 金额统一使用整数分：应付来自 `price`，可比官方优惠为 `originalPrice - price`。`discount` 是接口另列字段，不能与原价差叠加。结算能准确分解套餐且相同份量单点在售时，再核价同门店、同取餐方式、同餐具条件的单点购物袋；缺少完整份量或无法核价时不计算单点差额。
- 默认单餐预算 45 元、月预算 300 元。月预算用于支出复盘，不硬性阻止下单；0 表示不计划本月支出。满减差额只作提示，不按面值推断凑单收益。
- 常点收藏最多 20 组，只保存搭配组成，不永久保存旧券和旧价格。再次使用时重新搜索同份量搭配，检查最新营养、忌口和预算，选当前核价低的组合。条件变化或餐品下架时明确说明不可复用。
- `query-order` 同步本工具已创建订单。只有官方状态 2、4、6、8、10 且返回有效 `realTotalAmount` 才计入月支出；金额单位元，转为整数分。状态 1、7、未知状态不计入。优惠优先用官方 `totalDiscountAmount`，缺失时用可比 `totalAmount - realTotalAmount`，无法确认的金额不补零。
- 月统计按上海时区和订单创建月份，只覆盖本会话记录且已同步状态的订单，不代表所有渠道全部消费，也不是退款流水账。实际退款需在官方 App 核对。
