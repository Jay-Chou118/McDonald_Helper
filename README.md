# 麦搭 · Mai Pick

按官方营养、个人口味、天气和星期，从真实菜单、套餐、随心配和账户可用优惠券中找一顿实付更划算的麦当劳。独立个人工具，非麦当劳官方产品。

## 启动

需要 Node.js 20.19+ 或 22.12+。首次启动复制 `.env.example` 为 `.env.local`，其中只需要端口配置。每个浏览器会话在网页内连接自己的麦当劳账号。

```bash
npm install
npm run build
npm start
```

打开 **http://localhost:3001**。

开发模式：

```bash
npm run dev
```

打开 http://localhost:5173。Vite 将 API 请求转发到本机 3001 端口。

## 使用

1. 首次打开先看到连接引导：打开 [麦当劳开放平台](https://open.mcd.cn/mcp)，登录自己的账号，获取 MCP token，再粘贴到密码输入框中验证。验证成功后选择门店。无需在本工具注册账号。
2. 在「我的偏好」设定单餐热量范围、最低蛋白质、最高钠含量、单餐及月预算、口味及一周安排。
3. 点击「帮我搭一餐」，选择收藏餐厅，或输入城市和地址搜索餐厅。麦乐送使用账户中已保存的配送地址。
4. 查看最多三个不同主食的推荐，按官方核价后的实付金额从低到高排列。套餐会显示完整组成，优惠券会随餐品一起放入购物袋。也可以在「门店菜单」自行选品。
5. 「去结算」从官方 MCP 获取实时总价及配送、打包、餐具费用。到店订单需要选择官方返回的取餐方式。
6. 可在「优惠与领券」查看官方活动、本人到期券及门店可用券，点击「一键领取所有当前可领券」后自动刷新菜单并重新推荐。领取不会创建订单。
7. 核对后点击「确认提交，前往官方支付」，创建真实订单，再到官方支付页面付款。工具不自动付款。
8. 喜欢的推荐或购物袋可「存为常点」；「常点与预算」按今日优惠和当前营养条件重新搭配。同页同步官方支付状态，查看已确认消费、官方优惠和月预算余额。

选过的门店只保存在当前标签页的 `sessionStorage`，同一连接内刷新会恢复。不同城市的收藏门店需自行确认。天气使用「我的偏好」中设置的城市，切换异地餐厅时请同步修改。

## 会话与连接

- 浏览器通过服务端随机生成的 `HttpOnly`、`SameSite=Strict` Cookie 识别会话。不同浏览器、浏览器配置或独立的无痕会话分别连接；同一浏览器的标签页共享账号连接。清除 Cookie 后视为新会话。
- 每个会话拥有独立的 MCP 客户端、偏好、菜单、优惠券、地址和核价缓存，以及报价与本工具的订单记录。即使两个会话使用相同 token，也不会共享本地数据。每次连接有独立版本，旧标签页的请求被拒绝并返回首次连接/刷新流程。
- token 只存在于服务端内存；不写入 `.env.local`、状态 JSON、浏览器存储或响应。输入值在验证后清空。旧 `.env.local` 中的 `MCD_MCP_TOKEN` 不再用于网页连接，不会自动分配给新用户。
- 「连接设置」可验证新的 token。验证失败保留原连接；成功后切换连接版本，清空页面门店、购物袋、历史显示和报价。同一会话重新连接同一 token 可恢复该账号的偏好和记录，旧报价始终失效。
- 「断开连接并清除本会话数据」关闭客户端、撤销 Cookie，并删除该会话的偏好和报价/记录。其他会话不受影响。它不会撤销官方 token，也不会取消已创建的官方订单。
- 新会话自创建起有效 90 天，支持月度预算复盘，过期数据在一分钟内清理；旧版会话沿用原到期时间。服务重启保留未过期的偏好、常点和记录，但不保留 token，必须重新验证连接；重启前的报价不可提交。
- 每个会话一分钟最多验证五次连接；最多 200 个存续会话、每个连接最多 100 个缓存条目、每个会话账号最多 200 条保留的报价/订单记录。订单提交期间阻止切换和断开，避免一笔订单中途切换身份。
- 本机 API 校验请求来源、写入请求标记和连接版本。报价在所属会话与连接版本内校验，无法用另一个会话的报价下单。

## 推荐规则

- 使用 `list-nutrition-foods` 的官方营养记录，按标准份量计算 kcal、蛋白质、脂肪、碳水和钠。
- `query-meals` 获取菜单及价格，再用 `query-meal-detail` 确认份量和套餐组成。不会把「薯条」直接当作中薯，也不会把未匹配营养视为零。
- 展开最多四轮、每轮选一件的个人套餐，按所有组成部分计算营养。套餐和可选饮料传递父餐品编码、完整轮次及子项编码；优惠餐同时传递该账户可用的 `couponId`、`couponCode`。
- 推荐必须同时满足热量范围、最低蛋白质、最高钠、排除关键词、饮品和小食限制，以及官方实付预算。套餐内部也检查口味限制。无解时不会自动放宽条件。
- **实付低价优先**：先生成营养达标候选，按菜单估价从低到高选取最多 24 个，兼顾不同主食及不同优惠方案，再用 `calculate-price` 实时核价。按实际应付金额排序，同价时才考虑营养模式、喜欢的口味和天气。不同主食最多展示三个推荐。
- 推荐总价包含官方接口返回的配送、打包费用，不含餐具。结算时按实际餐具选择重新核价。
- **搜索范围有限**：并非全网或全菜单的全局最优证明。候选限定一份主食/套餐，按套餐缺少的类别补一份小食及一份饮品；不搜索多份套餐叠加、多个同类加购或跨平台优惠。领券后重新搜索当前菜单与可用券。每个套餐最多展开 20,000 个营养已知选项；复杂多选轮次保留合法默认组成。页面显示实际核价数量和未完全展开的提示。
- 「均衡一点」采用当天的一周安排；其他模式优先于星期安排。日期按 Asia/Shanghai 计算。
- 开启天气后，18°C 及以下优先热饮，27°C 及以上优先清爽饮品；有降水提示可考虑配送。「都可以」关闭饮品温度排序。
- 门店营业时段由官方实时菜单决定；天气或星期不会将不可售餐品加入推荐。

## 数据与边界

- **已接入真实官方 MCP**：`https://mcp.mcd.cn`，Streamable HTTP，服务端 Bearer 认证。仓库文档：https://github.com/M-China/mcd-mcp-server。
- **天气**：Open-Meteo 城市级实时数据，十分钟缓存；获取失败时显示天气不可用并关闭天气排序，不使用模拟天气。
- **价格与优惠券**：菜单价仅用于选择核价候选，推荐按官方实付价排序并筛选预算。自动查询本账户在当前门店可用的优惠券及优惠餐；券可用性以官方核价为准。优惠券查询失败会提示本次未覆盖；候选核价失败会移除并显示数量。默认查询不领券，用户点击领券后调用官方接口；不兑换积分或付费开卡。菜单缓存三分钟，推荐报价缓存 45 秒，结算时重新核价。
- **营养缺失**：营养未知餐品可手动加入购物袋，但完整营养总量显示未知，不参与自动推荐。组合必须有官方整餐营养或所有组成部分的营养才可参与推荐。
- **排除关键词**：只匹配餐品及已知套餐组成的名称。接口不提供完整配料或过敏原信息，关键词功能不能验证过敏原。
- **个别餐品详情失败**：低价套餐优先查询，并发最多三路；业务查询失败只重试一次，仍失败则从可选菜单中移除并显示提示。多人餐、周边及随单购会员卡不纳入个人餐品菜单。
- **记录**：记录本工具创建或提交结果待核实的订单；不导入全部历史订单，不把订单创建视为已付款。
- **领券与活动**：`available-coupons`、`campaign-calendar` 和分页 `query-my-coupons` 展示可领券、活动和本人券包。券包最多读取五页，每页 200 张，超出或失败时提示不完整。`auto-bind-coupons` 一次领取所有当前可领麦麦省券，不能按活动指定单张券。点击领取后刷新缓存和报价，再按门店重新核价。活动宣传价和只限 App 的券不直接计入本工具优惠。
- **省钱计算**：金额用整数分。展示同一购物袋的官方原价与实付差，不与接口 `discount` 重复累加。完整组成对应的单点餐品在售时，结算额外核价同门店、同份量、同取餐方式、同餐具条件的单点方案，展示两者差额；无法核对时不计算。满减门槛差额只提醒，不按券面值推断凑单收益。
- **常点与月预算**：最多保存 20 组搭配，再次使用会按新菜单、新优惠、最新营养和预算筛选并核价。默认月预算 300 元，是支出上限提醒而非花完目标，不硬性阻止下单。收藏、报价、未支付订单不算消费；手动同步 `query-order` 后，状态 2、4、6、8、10 且有有效 `realTotalAmount` 的本会话订单才计入支出。已取消或未知状态不计入；退款需在官方 App 核对。月统计按上海时区、订单创建月份，覆盖本会话已记录并同步的订单。
- **领券重复保护**：同一领券编号只执行一次，领券期间阻止提交订单和切换身份。结果不明时先核实官方券包，不自动重试；明确核实后可恢复查询。
- **提交保护**：报价三分钟内有效。创建订单前重新核验总价；价格变化要求重新结算。提交状态先原子写入本机存储，相同报价不能重复创建订单，网络失败不会自动重试创建。提交结果不明时需在官方 App 核实。
- **使用范围**：支持同一后端的多个隔离浏览器会话，仅监听 `localhost`，只允许本机域名来源；尚未部署到互联网。公开网站还需要服务器部署、HTTPS 和相应域名/来源配置。本工具没有独立注册系统，用户在官方平台登录后手动连接 token。

## 文件结构

```text
src/                  React 界面及响应式样式
server/index.mjs      有边界的业务 API，结算与订单提交
server/mcp.mjs        MCP 连接、协议响应提取、错误脱敏
server/sessions.mjs   浏览器会话、凭证生命周期、隔离与清理
server/data.mjs       每个连接独立的官方数据、天气、缓存及原子 JSON 存储
server/planner.mjs    营养映射、套餐替换、组合搜索和价格优先排序
server/value.mjs      低价候选选择、并发官方核价和实付预算筛选
server/offers.mjs     活动、券包、门店可用券和幂等领券
server/savings.mjs    整数分金额、同份量单点比较、月度消费汇总
src/Economy.jsx       优惠领券、结算金额、常点与预算页面
server/planner.test.mjs  营养与协议边界测试
server/sessions.test.mjs 双会话、连接切换、过期和订单边界测试
.env.local            服务端端口配置，不提交版本控制
.local/sessions/      隔离的本机偏好及报价、订单状态，不提交版本控制
```

`.local/sessions/` 使用服务端会话标识的散列和该会话凭证的散列作为目录名，不以原始 Cookie 或 token 作为文件路径。目录权限为 `0700`，状态文件为 `0600`。旧版 `.local/preferences.json`、`.local/quotes.json` 不自动导入任何新会话，避免泄露原使用者的数据；旧文件仍保留在本机。请不要分享 `.env.local` 或 `.local/`。

## 发布为 Skill

项目级 Skill 位于 `.trae/skills/mai-pick/`，上传包为根目录的 `mai-pick-skill.zip`。ZIP 内只有一个顶层目录 `mai-pick/`，入口是 `mai-pick/SKILL.md`，并显式包含目录条目。它只包含 Skill 指令、启动脚本、核价后端、网页源码和锁定依赖清单，不包含预构建网页、dist、node_modules、__pycache__、个人 token、`.env`、`.local` 或订单数据。

该版本是**本地运行的 Skill**：每个使用者安装同一份代码，在本人的本机浏览器连接本人账号。Skill 启动器把源码复制到当前操作系统用户的 `~/.mai-pick/`，安装依赖并在那里构建网页，再保存该用户的会话状态。默认地址为 `http://localhost:3011`，只监听 localhost；不会接管原网页的 3001 服务，也不会读取原项目的环境凭证。token 不经过 LLM 对话或扩展市场。

在 Skill 目录执行：

```bash
node scripts/launch.mjs --check
node scripts/launch.mjs --setup
node scripts/launch.mjs --serve
```

首次安装从 npm 官方源下载锁定依赖，并在用户私有目录构建网页；安装或构建失败时不标记为可运行。运行需要 Node.js、npm、本机执行能力和浏览器。需要其他端口时加 `--port 3012`。验证或受限环境可通过 `MAI_PICK_DATA_DIR` 指定本人的私有数据目录；不要指定与其他使用者共享的目录。

重新生成发布包：

```bash
node scripts/package-skill.mjs
```

打包脚本仅收集明确列出的后端、网页源码和 Skill 文件，不打包整个工作区；递归拒绝构建产物、临时目录、原始 IP 地址和硬编码 Bearer 凭证，校验名称和描述长度、相对引用及入口层级，再生成 ZIP。Skill 和运行源码包含 `.gitignore`，但发布包仍通过实际文件检查，不依赖 Git 忽略规则。打包工具需要本机 Python 3，Skill 使用者不需要 Python。

在 [扩展市场](https://skills.bytedance.net/contributors) 选择「创建 → 本地文件上传 → Skill」，选此 ZIP，并明确选择空间；上传窗口未选择空间时可能默认公共空间。平台的 [官方上传指南](https://bytedance.larkoffice.com/wiki/ToyIwp7mmibaiZkEKUocnYFAnQd) 规定子目录包含 `SKILL.md`，名称最多 64 字符，描述最多 1024 字符。指南示例为 `skills/doc-drafter/SKILL.md`，没有明确单独 ZIP 的扫描深度；本包选单个 Skill 目录以减少识别歧义。平台实际解析是否成功仍需要上传后确认。

上传仅分发指令和代码，不自动部署网页、生成个人 token 或配置每用户 MCP。当前未验证平台在线试用环境的 Node.js、浏览器和私密凭证能力；本包不能据此宣称支持纯聊天云端运行。共享同一份 Skill 与共享 token 是不同的事。如果未来要在云端直接点餐，需另接每用户授权的 MCP 或隔离后端。
